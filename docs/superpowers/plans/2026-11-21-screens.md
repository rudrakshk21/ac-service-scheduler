# Screens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline, no subagents: the owner manages usage limits). Steps use checkbox (`- [ ]`) syntax.

**Goal:** A phone-first front end on the engine and the intake library: workspace stored in the browser, a guided import, a data list, then the plan on real data and the site set-up.

**Architecture:** Pure logic (workspace changes, import flow reducer, view models) in tested modules; thin React screens on top; IndexedDB behind a two-method interface; hash-based tabs. No router, no UI framework, no state library.

**Tech Stack:** React 19, TypeScript 7 (strict, `erasableSyntaxOnly`, no parameter properties), Vite 8, Vitest 5 (node environment) + `fake-indexeddb` (dev), oxlint, the existing `src/engine` and `src/intake`.

**Spec:** `docs/superpowers/specs/2026-11-21-screens-design.md`.

```ts
// db.ts
export interface KeyValueStore { get(key: string): Promise<unknown>; set(key: string, value: unknown): Promise<void>; delete(key: string): Promise<void> }
export function memoryStore(): KeyValueStore
export function openIndexedStore(name?: string, factory?: IDBFactory): Promise<KeyValueStore>   // store 'kv'
// workspace.ts
export interface ImportRecord { at: string; fileName: string; kind: Kind; preview: ImportPreview }
export interface Workspace { workspaceVersion: 1; site: SiteProfile; technicians: ImportedTechnician[]; cases: StoredCase[]; profiles: MappingProfile[]; changes: ChangeLogEntry[]; imports: ImportRecord[] }
export class WorkspaceError extends Error {}
export function emptyWorkspace(): Workspace            // starterSite(), everything else empty
export function loadWorkspace(store: KeyValueStore): Promise<Workspace | null>   // null when nothing saved; WorkspaceError for a newer version or damaged data
export function saveWorkspace(store: KeyValueStore, w: Workspace): Promise<void> // key 'workspace'
// actions.ts
export function previewImport(w: Workspace, imported: Imported, date: string): ImportPreview
export function applyImport(w: Workspace, imported: Imported, profile: MappingProfile, fileName: string, date: string): { workspace: Workspace; preview: ImportPreview }
export function setCaseOverride(w: Workspace, caseId: string, o: Overrides): Workspace
export function profileFor(w: Workspace, kind: Kind, fingerprint: string): MappingProfile | undefined
```
- [ ] **Tests (db):** the memory store round-trips structured values and deletes; `openIndexedStore('t', new IDBFactory())` (from `fake-indexeddb`) round-trips a workspace-like object, keeps it after reopening the same factory, and `delete` removes it.
- [ ] **Tests (workspace):** `emptyWorkspace()` has the starter site and empty lists; save then load returns an equal workspace; load of an empty store is `null`; a stored `workspaceVersion: 2` throws a `WorkspaceError` whose message says the data was saved by a newer version and nothing is overwritten; a stored value that is not an object throws `WorkspaceError`.
- [ ] **Tests (actions):** `applyImport` for cases: cases merged (`mergeImport`), change log appended, import record appended with the preview and date, profile saved once per `(kind, fingerprint)` (a second import with the same fingerprint replaces it), site gets created places (`extendPlaces`), input not mutated; technicians: merged by normalised name (existing updated, new appended, none removed); places: added to the site once; `previewImport` equals the preview of `applyImport`; `setCaseOverride` merges into `overrides`, sets state `done` when `done: true`, and leaves other cases alone; `profileFor` finds by kind and fingerprint.
- [ ] **Implement** (`openIndexedStore`: `factory.open(name, 1)`, `onupgradeneeded` creates store `kv`; `get`/`set`/`delete` as promisified single-request transactions; reject with a plain `Error` on `onerror`/`onblocked`).

### Task A3: Import flow logic
**Files:** Create `src/screens/import/importFlow.ts`, `importFlow.test.ts`.
**Interfaces:**
```ts
export type Step = 'file' | 'columns' | 'values' | 'check' | 'done'
export function labelOf(field: string): string                       // 'caseId' -> 'Case identifier', 'workType' -> 'Work type', ...
export function levelOf(kind: Kind, field: string): 'required' | 'recommended' | 'optional'
export function guessKind(table: SourceTable, site: SiteProfile): Kind
export interface FieldRow { field: string; label: string; level: 'required' | 'recommended' | 'optional'; personal: boolean; suggestion: Suggestion | null; chosen: string[]; samples: string[][] }
export function fieldRows(kind: Kind, table: SourceTable, result: SuggestResult, profile: MappingProfile): FieldRow[]   // required first, then recommended, then optional; `chosen` from profile.columns; `samples` = 3 values per chosen column
export function setColumns(profile: MappingProfile, field: string, headers: string[]): MappingProfile   // [] removes the field
export type ValueField = 'workType' | 'status' | 'priority' | 'skill'
export interface ValueRow { source: string; count: number; target: string | null }   // target: site option name / action / null when unmapped
export function valueRows(table: SourceTable, profile: MappingProfile, site: SiteProfile, field: ValueField): ValueRow[]   // distinct normalised values with counts and the display spelling of the first; target resolved as the library does (profile map, own name)
export function valueOptions(site: SiteProfile, field: ValueField): { value: string; label: string }[]   // work types / skills / levels by name; status: schedule, hold, ignore with plain labels
export function setValue(profile: MappingProfile, field: ValueField, source: string, target: string | null): MappingProfile   // keys are normalised; null removes
export function needsValues(kind: Kind): ValueField[]    // cases: workType, status, priority; technicians: skill; places: []
export function canContinue(step: Step, state: { kind: Kind; profile: MappingProfile; rows: ValueRow[] ... }): { ok: boolean; reason: string }   // columns: all required mapped (cases need a location field too); values: no unmapped work type unless `leaveInReview`
```
Plus the reducer:
```ts
export interface FlowState { step: Step; fileName: string; table: SourceTable | null; kind: Kind; result: SuggestResult | null; profile: MappingProfile | null; knownProfile: boolean; leaveInReview: boolean; error: string | null }
export type FlowAction = { type: 'file'; table: SourceTable; fileName: string; kind: Kind; result: SuggestResult; known: MappingProfile | null } | { type: 'kind'; kind: Kind; result: SuggestResult } | { type: 'columns'; field: string; headers: string[] } | { type: 'dateOrder'; order: 'dmy' | 'mdy' | 'ymd' } | { type: 'value'; field: ValueField; source: string; target: string | null } | { type: 'leaveInReview'; on: boolean } | { type: 'next' } | { type: 'back' } | { type: 'error'; message: string } | { type: 'reset' } | { type: 'imported' }
export const initialFlow: FlowState
export function flowReducer(s: FlowState, a: FlowAction): FlowState
```
`next` from `file` goes to `columns` unless `knownProfile` (then `check`); from `columns` to `values` (skipped when `needsValues(kind)` has no unmapped rows and all mapped) else `check`; `back` mirrors it; `reset` returns `initialFlow`.
- [ ] **Tests:** labels cover every field of the model; `guessKind` picks technicians for `Name, Skills, Start Area`, places for `Place, Latitude, Longitude`, cases for `Ticket No, Category, Locality`, cases when unclear; `fieldRows` ordering, personal flag, samples; `setColumns` add/remove; `valueRows` counts, spelling, normalised merging (`AC Repair`, `ac repair `), targets from the profile map and from own names, unmapped is `null`; `setValue` keys normalised; `canContinue` for each step (cases need `caseId`, `workType` or `singleWorkType`, and a location field); reducer: file loaded goes to `columns` (or straight past it with a known profile), `next`/`back` order including the skipped values step, `columns` and `value` actions update the profile immutably, `reset`.
- [ ] Implement; full check; commit `feat(screens): import flow logic`.
